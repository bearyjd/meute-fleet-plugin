**Threat model, read before installing.** Paseo plugins run unsandboxed, as the daemon user: anything else running as that user (other plugins, agents) can read and rewrite this plugin and your Meute tree, and a second daemon under the same unix user isolates nothing. Supported deployment (PROPOSED, the owner's decision until confirmed): Meute and the operator Paseo daemon run as one dedicated unix user, with no third-party plugins and no other humans or services as that user, exposed on your tailnet or a VPN only; timer health works only when the daemon user owns the user bus, as it does in this layout. It is a deployment prerequisite, not something the plugin can enforce, that nobody but that user can write the Meute tree or the daemon user's files. A separate-user or group layout does not work: Meute writes its reports and state with umask 077, so a second user sees nothing. A paired device is the operator: any client with daemon.manage can call these views and can already install plugins. The plugin settings can be written by any client with daemon.manage, so the binary path, MEUTE_ROOT, PATH and XDG_RUNTIME_DIR you enter are a trust decision; before every Meute command the plugin re-checks the binary, MEUTE_ROOT and the whole Meute code tree, and refuses any of them owned by another user or writable by group or others; a directory above MEUTE_ROOT must be owned by the daemon user or root and not writable by group or others unless it has the sticky bit (like /tmp).

Meute Fleet is a read-only operator view of a Meute fleet that runs on the same machine as your Paseo daemon. It shows the findings inbox (filterable by state, severity and one or more repos, remembered on this client only), the readiness verdict, fleet health, and run status (lock holder, recent log lines, queue size), each with the time of its last answer. It cannot change anything in Meute.

It runs a small, fixed set of read-only `meute` commands as the daemon user and reads a few files under your Meute checkout. Meute gets a private, empty HOME made by the plugin (HOME is not configurable), so nothing in a home directory is loaded. Report text is shown as plain text, never as Markdown or HTML.

Setup: open Settings, Meute Fleet, and enter the absolute path of your Meute checkout (MEUTE_ROOT) and of `<MEUTE_ROOT>/bin/meute`. Readiness needs the paths of a readiness record and an owner policy JSON file. Health reads as unknown unless you also enter the daemon user's own XDG_RUNTIME_DIR (for example /run/user/1000) with a running user manager. Nothing is searched for or guessed. Requires Paseo 0.17 and Linux with `jq` and `python3` available to Meute.
